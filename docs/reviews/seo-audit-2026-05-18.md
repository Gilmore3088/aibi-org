**Surfaces audited:** 9 marketing routes on production (`https://www.aibankinginstitute.com`).

## Verification

```
$ curl -sI https://www.aibankinginstitute.com/courses/foundation/program
HTTP/2 307
location: /auth/login?next=%2Fcourses%2Ffoundation%2Fprogram
# ↑ confirmed S1 — production sitemap was pointing at a redirect

$ curl -sI https://www.aibankinginstitute.com/assessment/in-depth → 200
$ curl -sI https://www.aibankinginstitute.com/courses/foundation/program/purchase → 200
$ curl -sI https://www.aibankinginstitute.com/courses/foundation-preview → 200
  (foundation-preview carries robots: noindex — intentionally excluded)
```

Per-route HTML inspection of nine marketing pages confirmed zero `<link rel="canonical">` tags before fix, and `og:url` collapsed to `https://aibankinginstitute.com` on every route regardless of path.

---

## Fixes applied (this branch)

1. **`src/app/sitemap.ts`** — removed `/courses/foundation/program`; added `/assessment/in-depth` and `/courses/foundation/program/purchase`. Inline comment documents the auth-gate exclusion and the `robots: noindex` exclusion for `foundation-preview`.

2. **`src/app/layout.tsx`** — `SITE_URL` fallback now uses `https://www.${BRAND.domains.primary}` (www subdomain) instead of bare apex. Matches edge redirect behavior. Comment explains the apex-is-display-not-canonical distinction.

3. **Canonical tags on 8 marketing pages** — added `alternates: { canonical: '<path>' }` to:
   - `/` (page.tsx)
   - `/about`
   - `/education`
   - `/for-institutions`
   - `/security`
   - `/research`
   - `/assessment/in-depth`

   `/courses/foundation-preview` intentionally retains `robots: { index: false, follow: false }` and is omitted from sitemap.

   `/assessment` (the free 12-question entry) has no `metadata` export today — left untouched in this pass; canonical would need a new metadata export and a description. Filed as follow-up.
