1. Off-host redirect on /auth/confirm-device

The error helper hardcoded the production origin as the redirect base. Any failing token flow (expired, missing, already-used) bounced the visitor from preview or local deploys straight to aibankinginstitute.com, carrying the error string with it. Trust model assumed confirmation flows stay on-host.

Before

function redirectToLogin(message: string) {
  const url = new URL(
    `/auth/login?error=${encodeURIComponent(message)}`,
    'https://aibankinginstitute.com',
  );
  return NextResponse.redirect(url);
}

After

function redirectToLogin(origin: string, message: string) {
  const url = new URL(
    `/auth/login?error=${encodeURIComponent(message)}`,
    origin,
  );
  return NextResponse.redirect(url);
}

// origin captured from `new URL(request.url).origin`
// at the top of GET, threaded through every error path.

2. Trusted-device gate missing on two paid surfaces

/auth/login fails open on transient /api/auth/check-device errors with a comment that "trust is enforced at the layout level for protected surfaces." That claim was only true for two of four documented protected routes:

  • /dashboard — session check ✅, trusted-device check ✅
  • /courses/foundation/program — session ✅, trusted-device ✅
  • /my-toolbox — session ✅, trusted-device ❌ → ✅ now
  • /assessment/in-depth/access — session ✅, trusted-device ❌ → ✅ now

Both routes now call isDeviceTrusted({ userId, cookieToken }) with the aibi-trusted-device cookie value; failures redirect to /auth/confirm-device-pending with the user's email preserved. Pattern mirrors the /dashboard layout exactly.

Before — /my-toolbox

const { data: { user } } = await supabase.auth.getUser();
if (!user) redirect(loginHref);

return <ToolboxPage />;

After — /my-toolbox

const { data: { user } } = await supabase.auth.getUser();
if (!user) redirect(loginHref);

const trustedCookie = cookieStore.get(TRUSTED_DEVICE_COOKIE)?.value;
if (!(await isDeviceTrusted({
  userId: user.id, cookieToken: trustedCookie,
}))) {
  redirect(`/auth/confirm-device-pending?email=` +
    encodeURIComponent(user.email ?? ''));
}

return <ToolboxPage />;

3. Webhook silently 200-OK'd every non-checkout event

The handler returned { received: true } with no log line for anything that wasn't checkout.session.completed. Three of the four required live-endpoint events (payment_intent.succeeded, payment_intent.payment_failed, charge.refunded) left no forensic trail.

Every received event is now logged at info on entry. Failed payments additionally fire purchase_failed analytics with the last_payment_error.code.

Before

if (event.type !== 'checkout.session.completed') {
  return NextResponse.json({ received: true });
}

After

console.info('[webhook] received', {
  type: event.type, id: event.id,
});

if (event.type === 'payment_intent.payment_failed') {
  const pi = event.data.object as Stripe.PaymentIntent;
  console.warn('[webhook] payment_intent.payment_failed', { … });
  void trackServer('purchase_failed', {
    stripePaymentIntentId: pi.id,
    reason: pi.last_payment_error?.code ?? 'unknown',
  });
  return NextResponse.json({ received: true });
}

4. Refunds did not revoke course access

charge.refunded was silently 200'd. A buyer who got a refund kept their course_enrollments row, and the entitlements trigger never fired, so Toolbox + Foundation course access stayed live.

The new handler:

  • Reads payment_intent from the Charge object
  • Calls stripe.checkout.sessions.list to resolve the session id
  • Deletes the matching course_enrollments row via service-role client
  • Migration 00015_entitlements_trigger flips entitlements.active = false and stamps revoked_at automatically
  • Fires purchase_refunded analytics with the refunded amount

After (excerpt)

if (event.type === 'charge.refunded') {
  const charge = event.data.object as Stripe.Charge;
  const paymentIntentId = typeof charge.payment_intent === 'string'
    ? charge.payment_intent
    : charge.payment_intent?.id;

  const sessions = await stripe.checkout.sessions.list({
    payment_intent: paymentIntentId, limit: 1,
  });
  const sessionId = sessions.data[0]?.id;

  const supabase = createServiceRoleClient();
  const { error, count } = await supabase
    .from('course_enrollments')
    .delete({ count: 'exact' })
    .eq('stripe_session_id', sessionId);

  // entitlements trigger (migration 00015) revokes Toolbox access.
  return NextResponse.json({ received: true });
}
