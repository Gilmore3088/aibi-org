Safe vs. Unsafe Prompt Examples

Use these examples to teach bankers how to strip sensitive data, ask for draft support, mark uncertainty, and route risky output to review.

Example pairs

The safer prompt changes the input, the job, and the review rule.

Unsafe promptSafer prompt
Customer service: Summarize John Smith's account issue and draft a response about why his debit card transaction was denied. Customer service: Using only the redacted facts below, draft a customer-service response template. Do not include account numbers, balances, transaction details, eligibility decisions, fraud conclusions, or promises. Mark missing facts as [VERIFY]. Output as a draft pending banker review.
Credit: Write the adverse-action notice and decide the best reason to deny this applicant. Credit: Using only [HUMAN_PROVIDED_REASONS], rewrite the draft explanation for clarity. Do not add, infer, rank, approve, deny, or decide. Mark unsupported language as [VERIFY].
BSA/AML: Improve this real SAR narrative from the case system and make it more persuasive. BSA/AML: Using [SYNTHETIC_CASE_FACTS] only, create a fictional training example organized by who, what, when, where, why, how, missing facts, and reviewer checklist.
Complaints: Use these complaint notes to tell me what we should offer the customer. Complaints: Using [COMPLAINT_SUMMARY], draft a neutral issue summary and list missing facts. Do not determine fault, offer remediation, or promise outcomes. Route to [REVIEWER].
Marketing: Make this ad more persuasive and add claims about how much customers will save. Marketing: Rewrite this approved campaign draft for clarity. Do not add performance claims, rates, fees, guarantees, eligibility promises, testimonials, or disclosures. Mark unsupported claims as [VERIFY].
Operations: Review these real wire details and tell me whether the payment is suspicious. Operations: Using [APPROVED_PROCEDURE_SUMMARY], create a staff checklist for routing wire-review questions. Do not assess a real transaction or make a fraud conclusion. Escalate exceptions to [REVIEWER].
Pattern

What the safe prompt does differently.

1

It replaces specifics.

Real customers, accounts, transactions, complaints, SAR facts, credentials, and examiner-sensitive facts become placeholders or are removed.

2

It narrows the job.

The prompt asks for draft support, not a decision, approval, denial, investigation, filing, or final answer.

3

It controls the output.

The prompt names the format and forbids invented facts, unsupported claims, promises, and sensitive details.

4

It names review.

Uncertain items are marked [VERIFY], and the reviewer or escalation trigger is named before downstream use.

Stop rule

If the prompt still reveals a real customer, investigation, SAR, complaint, loan file, fraud case, security issue, credential, or production detail, escalate instead of prompting.
