Scenario Practice

Three reps every InfoSec team should run.

Sandbox scenarios let the team practice classification, vendor DDQ, and incident response with synthetic facts.

Active Sandbox Scenario
Classification · Lending Memo Draft
Input
A lender wants to use a public LLM to polish the prose of an internal credit memo. The memo contains the borrower's name, address, FICO, and balance information.
Prompt
Classify the data in this memo against our four-tier matrix. List what must be redacted before any external tool can touch it, and what the lender can do instead within our sanctioned stack.
Expected Output
Classification: Restricted PII / GLBA NPI. Required redactions: name, address, FICO, balance. Alternative: use the bank's enterprise-tenant LLM with DLP — no public-tool route.

SaaS discovery, browser-extension audit, employee survey. The inventory is the foundation of every other control.

Four tiers, plain language, real examples. The classification has to be teachable in 10 minutes.

FFIEC + Interagency Guidance. SOC 2, sub-processors, training-data policy, contract clauses that actually matter.

Monitoring

Egress logs, DLP, SaaS discovery, monthly exposure report to the IT committee.

Pre-approval Checklist
Before any AI tool goes on the allow list
Vendor SOC 2 Type II current; report reviewed
Contract prohibits training on bank inputs (or carve-out documented)
SSO + MFA enforced; no shared accounts
Data class explicitly named on the tool card (public / internal / confidential / PII)
Retention policy aligned to bank schedule
Geographic processing within US (or approved exception)
Business owner named; review cadence set (annual minimum)
